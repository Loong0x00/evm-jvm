# Stock S2b link/parser split preflight

**Status: proposal and ignored prototype only. Nothing in this document freezes
S2b.** Base is `3098849993486c7d016da947ebd7836480a3fa90` (`3098849`), while the
parent is still final-gating the frozen 201-row S2a slice. The only tracked change
is this document. Reproducible prototype inputs, Solidity, artifacts and logs are
under ignored `build/java-diff-stock-s2b-link/`; they are not production inputs or
artifacts.

S0, S1, S2a, their registries/pages/live coordinators, the old fixtures and the
154,839-byte monolith are unchanged. This work did not execute S2b through a stock
frame machine and makes no 268-row stock-execution claim. It used no `SetCode`,
`SetState`, executable injection, AOT/class-specific executable, host CP/offset/
callee metadata, Java fallback, core/opcode/gas/consensus/limit change, listener,
downloaded Java, Minecraft or EULA action.

## Recommendation

After S2a acceptance, freeze a **registration-only S2b-L slice** before a frame
executor. Use a new schema/domain version (candidate version **4**) and an ordinary
deployed-EVM `ClassLinker` + `AnalyzeModule` split. The linker reads an unchanged
raw `STOP || classfile` page, checks its page/payload hashes, and passes the raw
bytes to a code-hash-pinned analyzer. The analyzer reparses the class/CP/methods,
predecodes bytecode, resolves same-class calls, and returns bounded metadata. The
linker checks dimensions and creates `STOP || metadata` with ordinary internal
`CREATE`. No host-derived CP index, Code offset, target method, descriptor, start
map, literal or call record is accepted.

This is required rather than renaming S2a metadata. Frozen S2a schema 3 has six
header words, four words/method and no calls. Its class IDs and live one-frame
states cannot encode or upgrade to S2b calls. Candidate S2b schema 4 has a new
class ID and metadata page. An EVM-side adapter should:

1. pin the accepted S2a parser code hash;
2. read and hash-check the S2a `classRecord` metadata page;
3. validate the schema-3 header and extract its raw page/page hash/payload hash;
4. reread and reparse that unchanged raw page through the S2b analyzer; and
5. issue a new schema-4 page/class ID.

The same internal registration path accepts the three new M3a raw pages directly.
The adapter must not copy S2a Code-derived fields as authority. Existing S2a pages,
class IDs and coordinators remain usable and unchanged; schema-3 and schema-4
program/state IDs are intentionally not interchangeable.

## Candidate schema-4 metadata

Keep raw<=4,096 bytes, CP<=512, declared methods<=32, eligible Code<=256,
stack/locals<=8, eligible literals<=256 and eligible calls<=32. Internal callable
methods may be private, package, protected or public, but must be static and not
native, abstract, synchronized or otherwise forbidden. Their exact descriptors
are `(I{0..6})I` or `(I{0..6})V`. A selected root remains unambiguous public static,
returns `I`, and takes 0..6 ints. Predecode/flow adds `pop`, `invokestatic`, `return`
and descriptor-dependent call effects while retaining all S2a integer forms.
Recursive graphs are records, not recursive analyzer execution.

Candidate payload is exactly:

```text
8*32 header + methods*5*32 + literals*8 + calls*16
```

Thus the simultaneous maximum is **7,936 payload bytes / 7,937 STOP-runtime
bytes**, below the 8,192-byte candidate page ceiling. All integers below are
big-endian within compact records. Proposed exact layout:

- H0 schema magic; H1 raw page/address + class access; H2 page code hash; H3 raw
  payload hash; H4 declared-class-name hash; H5 raw length/CP/method/literal/call
  counts; H6 analyzer revision; H7 reserved zero.
- Five method words: name hash; descriptor hash; packed declared index/access,
  Code offset/length, max stack/locals, argc, return kind (`0=V,1=I`), deferred
  error domain/code/location, literal base/count and call base/count; 256-bit
  instruction-start map; reserved zero.
- Literal: `(method:u16, pc:u16, intBits:u32)`.
- Call: `(caller:u16, pc:u16, cpIndex:u16, target:u16, argc:u8,
  returnKind:u8, flags:u16=0, reserved:u32=0)`.

For each `invokestatic`, the analyzer requires `CONSTANT_Methodref` tag 10,
resolves its Class and NameAndType/Utf8 chains, compares the symbolic owner name
to the declared class name, and finds exactly one declared target by name **and
descriptor**. The target profile/access/Code is independently checked. Runtime
must check opcode+CP operand against the immutable caller/PC call record, then use
the cached target/argc/return kind; recursion must not rescan CP. Interface refs,
external owners and reference/category-2 descriptors remain unsupported.

Candidate identity is domain-separated and pins actual deployed code:

```text
classId = H(DS2B_LINK_CLASS, uint32(4), linkerCodeHash, analyzerCodeHash,
            rawPage, rawPageHash, payloadHash, metadataHash)
```

The linker constructor verifies the analyzer `EXTCODEHASH` and stores both address
and hash immutably. Its own actual runtime hash binds the metadata-page creation
code. Registration verifies raw and metadata code hashes. Future `programId` must
also pin schema 4, class ID, root index/name/descriptor, step-module code hash and
frame-store implementation/template hash. Supplied addresses/hashes remain
configuration commitments, not attestations.

## Prototype coverage and remaining uncertainty

Covered by deployed EVM: Java52/CP parsing, method envelopes, public/private/
package/protected static profile, exact 0..6-int `I`/`V` descriptors, Code<=256,
all current scalar opcodes, `pop`/`return`/`invokestatic` widths and flow effects,
same-class tag-10 owner/name+descriptor target resolution, overloads, recursion
records, bounded literal/call caches, metadata `CREATE`, registry provenance,
all 14 positive classes and the simultaneous valid cap.

Not covered and therefore not acceptance evidence:

- no frame store, call/return execution, call cache consumption, 128-frame outcome,
  resume, rollback or 67-row stock execution;
- no production S2a adapter, root selector/program IDs, idempotent-return counts,
  analyzer-call return-data hardening, complete custom-error precedence or negative
  mutation matrix;
- the prototype reduced the flow work queue to `CodeLength+1` entries to fit the
  measured cap. It rejects on overflow and passed this corpus, but this is not a
  proof for every legal branch/definite-local graph. Production should use a
  bounded de-duplicated/ring worklist (or prove a tighter enqueue bound), then
  rerun the 8M cap rather than inheriting this shortcut;
- the valid-cap class intentionally puts literal blocks behind verified branches
  to exercise immutable cache capacity without maximizing reachable-flow work.
  It proves the exact metadata dimensions and registration transaction, not every
  combination of maximum Code control-flow complexity.

Required S2b-L negatives before freeze: malformed/truncated or non-tag-10 CP refs;
Class/NameAndType/Utf8 chain errors; external owner and InterfaceMethodref; missing
or duplicate exact target; wrong overload descriptor; nonstatic/native/abstract/
synchronized target; malformed/reference/category-2 descriptor; locals<argc;
`ireturn`/`return` mismatch; invoke underflow; six-argument order; caller prefix;
call 32 success/33 rejection; methods 32/33, literals 256/257 and metadata length
boundaries; wrong page/payload/analyzer/linker/metadata hash; duplicate registration;
metadata CREATE failure; 8M exact-cap success plus one-less/OOG rollback and retry.
Call linkage/validation errors remain EVM errors, never Java faults.

## Parallel frame-store preflight, still not frozen

Do not revive the old 16-frame/192-word/800k-reserve proposal. Its measured
~3.8M child writes preceded semantic/provenance costs, and 192 cold zero-to-nonzero
slots alone exceed 4.2M. Run a separate ignored preflight against schema 4 while
S2b-L is reviewed.

For the integer-only frame candidate, pack three 65-bit tagged int cells per word.
A frame uses one packed identity/control word, `parentRoot`, `frameRoot`, three
stack words and three local words (nine maximum slots); inactive cells remain zero.
A newly called frame normally writes control + roots + at most two local words,
not 16 unpacked cells. IDs are monotonic `uint64`; root is 1; active depth is
explicit and capped at 128. Deleted child slots are cleared. This packing is
versioned integer-only and must not be presented as a future reference/category-2
layout.

Candidate preflight interfaces:

```solidity
FrameStoreV4.load(uint64 frameId) view returns (PackedFrameV4);
FrameStoreV4.apply(uint64 expectedEpoch, FrameDeltaV4[] calldata sorted,
                   HeaderCommitV4 calldata commit); // coordinator only
StepModuleV4.step(ProgramV4 calldata program, address store,
                  HeaderV4 calldata before, uint16 maxSteps,
                  uint8 maxDirtyFrames, uint8 maxDirtySlots)
  view returns (HeaderV4 after_, FrameDeltaV4[] memory delta,
                uint16 executed, uint8 dirtyFrames, uint8 dirtySlots);
CoordinatorV4.resume(uint64 expectedEpoch, uint16 maxSteps,
                     uint8 maxDirtyFrames, uint8 maxDirtySlots);
```

Start measurement at `maxSteps=128`, `maxDirtyFrames=2`, `maxDirtySlots=16` so one
complete call or return always fits; stop before a second frame-boundary operation
if it would exceed the cap. Every `invokestatic`/return is indivisible. The module
is `STATICCALL`-only; only the coordinator-owned store applies sorted unique deltas.
Reserve must be derived from measured slot classes, including cold zero->nonzero,
reset, clear, coordinator headers, hashing, ABI validation and event cost. Do not
reuse 800,000 by name. Require successful call, return, recursion-depth transitions,
dirty=`actual`, dirty=`actual-1` rollback/retry and nested OOG under the existing
2M resume target; refactor packing/batch size if that fails.

Frame negatives must include parent/invoke-PC/link mismatch, duplicate/unsorted ID,
create-overwrite/delete-missing, nonmonotonic next ID, depth/current mismatch,
noncanonical packed cells/reserved bits, partial argument transfer, I/V return
shape, expression-prefix/local isolation, stale epoch, malicious module deltas,
call at depth128 (kind2 counted once) versus low-gas OOG, callee arithmetic identity,
and rollback after store writes but before coordinator/event completion. The
existing trusted SOE fixture is enough; do not add host-exhaustion workloads.
