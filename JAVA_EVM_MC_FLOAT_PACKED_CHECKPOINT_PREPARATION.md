## One semantics-preserving transport change
Keep guest heap arrays eagerly materialized `uint64[]` and Java bytecodes entirely unchanged. Extend the canonical MR01 checkpoint wire with a distinct `float[ ]` packed flag in the existing u32 count word (candidate bit30; existing sparse-pair bit31 remains). For large rank1 primitive-float arrays only, encode each *actual* guest `uint64` cell in four bytes **iff** every cell fits uint32 (IEEE754 binary32 raw bits). Explicitly reject impossible high bits, malformed flags, wrong rank/type, truncated payload, invalid count and noncanonical format. Decode must eagerly reconstruct the exact dense `uint64[]`; never lazy-load, inject a table, perform host math/ZIP/class parsing, accept failed state, weaken root/codehash commitments or change unrelated primitive/reference arrays. Preserve signed zero, NaN payloads and all 32-bit patterns bit-for-bit. Canonical format selection must compare bytes: old sparse pair (u32 count + 12*n) versus packed float (4*length) versus dense (8*length); choose packed when it is strictly smaller than the eligible sparse record for the same actual array (and length>=1024), else retain old canonical sparse/dense. If source would truncate or canonical re-encoding differs, atomically refuse.

Only measured checkpoint helpers (`_machineSize`, `_encodeMachine`, `_decodeMachine` and narrowly required float-layout helpers/constants) may change. Preserve bounded integer `Math.sin`, 97-image bootstrap source/ordered root, native19/String-local12, raw71/471911, VFS0a/AS0/ZI0/DI0/MR0/CB0 and bytecode runtime<=393216.
