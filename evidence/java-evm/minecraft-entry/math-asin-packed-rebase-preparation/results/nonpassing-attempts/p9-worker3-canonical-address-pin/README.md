# Preserved nonpassing P9 gate attempt

`invocation.json` and `failure.log` are the exact canonical-receipt verifier records from generated gate worker3. The full generated world matrix had run, but the final strict receipt verifier failed because that build's inherited `pins.json` still named the P6 engine address (`...5031000e`) while the P9 receipts correctly named P9 (`...5039000e`). This is a harness/build-pin mismatch; worker3 is **not** a passing gate and none of its execution is credited as acceptance. The build script was corrected to emit P9 engine/owner addresses, then the entire generated gate was freshly rerun as worker4; its 6,112 canonical receipts passed. The worker4 evidence is archived separately in `../generated-gate-p9/`. No original inputs or P8 state were used by either generated attempt.
